# 失败案例归因记录（W02）

> 方法：人为制造一类失败请求，记录「现象 → 异常类型 → 环节定位 → 改进建议」。
> 下表按调用链路分段，便于对照定位卡在哪一环。

## 调用链路分段

1. **配置 / 鉴权**：API Key 是否存在、是否有效、是否带 `Bearer`。
2. **网络 / 连接**：base_url 是否可达、DNS、代理、超时、连接中断。
3. **请求参数**：模型名、messages 结构、长度上限、参数取值是否合法。
4. **响应解析**：HTTP 状态码、返回 JSON 结构、字段是否齐全。

## 案例 1：缺少 / 无效的 API Key（鉴权环节）

- **触发方式**：不配置 `LLM_API_KEY`，或填一个过期 / 错误的 Key。
- **观察现象**：
  - 未配置 Key：客户端在发请求前直接抛出 `缺少 API Key，无法调用模型`（本地前置校验）。
  - 错误 Key：请求发出后接口返回 `401 Unauthorized`，被包装为 `模型接口返回 401：...`。
- **异常类型**：`RuntimeError`（源自 `httpx.HTTPStatusError`，状态码 401）。
- **环节定位**：鉴权环节（第 1 段）。不是网络问题，也不是参数格式问题。
- **改进建议**：
  - 启动时前置校验 Key 是否为空，给出明确提示（已实现）。
  - 后续可按状态码细分：401/403 提示检查 Key 与权限，429 提示限流退避。

## 案例 2：请求超时（网络 / 连接环节）

- **触发方式**：把 `LLM_TIMEOUT` 设为 1s，或在网络不通时请求大模型。
- **观察现象**：等待约 1s 后抛出 `模型请求超时（1.0s）`。
- **异常类型**：`RuntimeError`（源自 `httpx.TimeoutException`）。
- **环节定位**：网络 / 连接环节（第 2 段）。服务可能可达但响应慢，或链路不通。
- **改进建议**：
  - 超时按任务类型设置合理默认值；并发场景单独控制每个请求超时。
  - 后续可加有限次数的重试与指数退避。

## 案例 3：base_url 或模型名错误（请求参数 / 路由环节）

- **触发方式**：base_url 末尾路径错误，或填入平台不存在的模型名。
- **观察现象**：通常返回 `404 Not Found` 或 `400 Bad Request`，响应体带错误说明。
- **异常类型**：`RuntimeError`（源自 `httpx.HTTPStatusError`）。
- **环节定位**：请求参数 / 路由环节（第 3 段）。鉴权已通过，问题在地址或模型名。
- **改进建议**：
  - 报错时把响应体原文带出来，便于对照平台文档修正。
  - 配置示例中注明各兼容服务的 base_url 与可用模型名。

## 案例 4：响应结构异常（解析环节）

- **触发方式**：接口返回非预期 JSON（如错误页 HTML、缺 `choices` 字段）。
- **观察现象**：解析时抛出 `模型响应格式异常：...`。
- **异常类型**：`RuntimeError`（源自 `KeyError / IndexError / TypeError / ValueError`）。
- **环节定位**：响应解析环节（第 4 段）。请求本身已到达服务，是返回结构与预期不符。
- **改进建议**：
  - 解析前先判断 `choices` 是否存在；缺失时给出可读提示。
  - 后续结构化输出（W03）增加字段校验与兜底重试。

## 归因对照表

| 现象关键词 | 最可能环节 | 状态码 / 异常 |
|---|---|---|
| 缺少 API Key、401、403 | 鉴权 | 前置校验 / HTTP 401/403 |
| 超时、连接中断、DNS 失败 | 网络 / 连接 | `TimeoutException` / `ConnectError` |
| 404、400、模型不存在 | 请求参数 / 路由 | HTTP 400/404 |
| 缺字段、JSON 解析失败 | 响应解析 | `KeyError` / `JSONDecodeError` |
